Behind Lumen

Origin · Method · Outcome

In mid-2025, I joined the challenge of helping build a Design System for a global company — structuring scalable UI foundations, organising components, contributing to the Storybook architecture, and shaping a unified product experience across platforms.

Lumen is the conceptual recreation of that experience. Working independently and from scratch, I rebuilt selected components and patterns through modern AI-assisted development workflows — designing in Figma and translating those decisions into production-ready interfaces with Claude Code as a pair-programmer.

The goal isn't to replicate the original system. It's to demonstrate how the same craft — tokens, component lifecycles, documentation structure, design-engineering hand-off — can be condensed into a focused, portfolio-scale laboratory that anyone can read in one sitting.

Changelog

Lumen follows semantic versioning — major.minor.patch — so consumers always know the impact of an upgrade.

v0.3.0 February 2026 · MINOR

First public preview

  • Tokens, twenty components, three patterns, demo app.

Versioning

Three rules govern when a release bumps which number:

MAJOR

X.y.z — breaking change

A redesigned component, removed property, or any change consumers must migrate to.

MINOR

x.Y.z — additive

A new component, a new state, or a non-breaking enhancement to an existing one.

PATCH

x.y.Z — fix

A bug-fix, a spacing tweak, an accessibility improvement — anything fully backward-compatible.
